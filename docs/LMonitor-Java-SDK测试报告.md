### 计时与质量口径

System.nanoTime 记录 callMs：从 startMonitor 前到同步返回后，包含参数转换、JNA 内存复制、原生解码与解算、解析和回调；文件读取、JVM 启动与库加载不计入。offTime 是原生结果文本，不替代端到端时延。

相同输入重复 4 次，首次单列，后 3 次统计；5 MB 执行 3 次，首次单列，后 2 次统计；P95 使用最近秩法，小样本时即最大值。双线程仅运行 2 轮用于一致性观察，不据此推导最佳并发数。

严格质量条件为恰好一次回调、无异常、有限 ENU、errMsg 为空、fileStatus/navStatus 为 0、最终 Fixed 且固定率不低于 0.75。性能测试没有专用空闲主机、固定 CPU 频率或经确认的 SLO，报告值仅作本机基线。

### 绝对精度与逐历元验证

本轮未提供独立同期坐标或位移真值，未采集逐历元位置序列，不能报告绝对误差 RMSE、95% 误差或固定解 ENU 标准差。基线长度约 35.75 km 是 RTCM 参考 ECEF 的几何距离，不作为精度验收依据。

正式精度试验应记录基站 ECEF、ENU 原点和方向、天线高、坐标框架、时间系统及真值不确定度。按项目短/中/长基线分组覆盖多个站对和时段，分别统计全量历元与固定解子集。

对匹配历元计算 eE=E−E真、eN=N−N真、eU=U−U真，报告轴向偏差、RMSE、水平/垂向 P95、最大误差、可用率和固定率。保留失锁、非固定与异常结果；当前 dposmax/dposavg/dposstd 不直接替代真值误差。

### 真实位移反应时间尚未验收

真实位移反应时间应从位移发生时刻 t0 到可靠识别时刻 tdet，以 tdet−t0 计量。当前样本没有位移时刻和幅值真值，文件回放耗时、首次固定或 offTime 不能替代该指标。原生返回一次汇总结果，不等同实时历元到达。

filterPeriod/processInterval 只复制到结果，不建立调度；warmupMin 则已传入原生库，本轮为 0，未测试非零预热。需要预热时必须提供覆盖预热期的观测，并明确有效统计区间。

### 受控位移试验建议

使用时间同步的位移台、全站仪或可信 GNSS 仿真器，设置水平和垂向阶跃，覆盖冷启动、已固定、失锁恢复及无位移对照。事先约定幅值误差带、连续 K 个有效历元规则与告警阈值。

记录采集、接收、排队、计算和回调时间戳，统计首次越阈与稳定响应的 P50/P95/最大值、漏检率、误报率。无响应轮次保留在失败分母内。幅值和响应阈值需由验收要求确定。

### 结论边界

这是包含解码的 SDK 全流程结果。当前 Java API 没有 decode-only 入口或解码阶段埋点，不能称为纯 RTCM 解码性能。测量样本只有 2 次，不代表生产尾延迟；本轮未采样峰值 RSS或长期内存回落。

12 小时有效窗获得较高固定率，不能推断系统需等待 12 小时才识别位移。尚需验证精确 5 MiB、每站 5 MB、10/50 MB、异常帧、精密星历和持续循环，并与约定的时延/容量指标比较。

## 七 多任务并发与平台覆盖

### 双线程任务一致性

三项任务与串行基线相同：short-13、long-12、long-13。两轮共 6 次调用，各自构建 MonitorTask 与 JNA 内存；共享默认服务和一次固定注册的回调，通过 extra 关联结果，不使用共享 outFile。

| --- | --- | --- | --- |
| 串行基线 | 889.13 | 3 / 3 | 参考值 |

| 双线程第 2 轮 | 832.09 | 3 / 3 | 13 字段一致 |

比较字段为 ENU、固定率、解状态、文件/星历状态、错误、时间、双站历元数和历元率。6 次无 Java 异常或进程崩溃，但三项基线原有固定率告警全部保留，不能算作质量通过。

只有一个并发档和两轮样本，且串行与并发没有充分匹配预热，不能据此声称加速或线程安全。默认 Java 服务未使用 synchronizedLibrary，回调槽位可覆盖；需补测 1/2/4/8 档、锁保护对照、异常混跑与长时压力。
